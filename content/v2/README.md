# content/v2 — per-building inputs for the painted village (v2)

The v2 shell (`village/v2/index.html`, `app.js`, `style.css`, `data/map.js`, `map/`) is **shared and frozen**.
Buildings are discovered **at runtime**: `data/map.js` lists all six buildings on the map painting
(église, mairie, école, garage, boulangerie, café). On load the map tries `village/v2/data/<bld>.js` for each one;
a building whose data file loads is **live** (clickable, opens `#/<bld>`), every other one shows **bientôt**.
Nothing has to be registered anywhere.

## The per-building rule (for every worker)

A building tarball (`v2-<bld>.tar.gz`) **only adds** these paths:

| path | what |
|---|---|
| `content/v2/<bld>/layout.json` | rooms, painting file names, hotspot boxes (1280×720 px), doors, map exit, zooms, `planned` word lists |
| `content/v2/<bld>/hooks.json` | optional hook overrides `{word_id: {"hook": "...", "why": "..."}}` |
| `village/v2/<bld>/*.jpg` | one integrated painting per room (1280×720, JPEG q≈86 progressive) |
| `village/v2/<bld>/cards/*.webp` | card crops (generated by the build) |
| `village/v2/data/<bld>.js` | generated payload (`build_v2.py`) |

It **never edits** `village/v2/index.html`, `app.js`, `style.css`, `README.md`, `CHANGES.md`, `data/map.js`,
`map/`, `content/v2/map.json`, `scripts/v2/*`, `scripts/qa/*`, another building's files, or anything outside v2
(v1 data, `data/source/`, `content/rooms/`, …). If you think a shared file must change, stop and report it instead.
Put your change notes in the tarball's top-level `CHANGES.md`, not in the repo.

## Workflow

```
python3 scripts/v2/build_v2.py <bld>                 # writes village/v2/data/<bld>.js + cards
python3 scripts/qa/check_v2.py <bld>                  # static rules
(cd village && python3 -m http.server 8765) &
python3 scripts/qa/check_v2.py <bld> --browser        # rendered overlaps, Back, verb cards, map shows <bld> live
```
QA must print `PASS`. Then look at every hotspot yourself: the painting must show what the hook says.

## layout.json

```jsonc
{ "building": "boulangerie", "name": "La boulangerie", "main": "boulangerie",
  "roomList": [{"key": "boulangerie", "short": "La boutique"}, ...],     // main room first
  "rooms": { "<key>": {
     "name": "...", "image": "<bld>/<key>.jpg", "alt": "...", "nameplate": [50, 4.5],
     "planned": {"vocabRoom": "R_..."} | {"v1": "<bld>/<room>"} , "only": [ids...] (optional),
     "mapExit": {"box": [x,y,w,h], "label": "Le village"},              // MAIN room only, on a painted exit
     "doors": [{"to": "<key>", "label": "...", "hint": "...", "hit": [x,y,w,h]}],  // on a painted door
     "backTo": "<main>",                                                   // sub-rooms
     "zooms": [{"to": "<key>", "label": "...", "at": [x,y], "obj": [x,y,w,h]}], // obj = the object in this painting
     "parent": "<key>" (zoom rooms),
     "items": [{"id": "fr_..._noun", "box": [x,y,w,h], "labelAt": [cx, top] (optional), "text": "vocab" (optional)}]
  } } }
```
* Card text comes from the v1 payload `village/assets/data/<bld>.js` (matched by id), else `data/source/vocab.jsonl`;
  `"text": "vocab"` forces the vocab source. Never copy or edit that text.
* `hooks.json` is only for hooks that break the content rules (crude, scary, drinking/smoking, mature, God the
  Father…) or that cannot be painted; the painting must then show the new hook.

## Rules every painting must satisfy
Ink-outline storybook gouache, whimsical; nothing written in the paintings; each hotspot's object shows its hook;
feminine words in the LEFT half, masculine in the RIGHT (epicene 30–70 %); no overlapping hotspots, labels, doors;
every passage is a painted door with its hit box on it; the main room has a painted exit to the village; zoom
objects are visible in the parent and match it; age-appropriate content; scenes consistent with each other and
with the building on the map painting.
