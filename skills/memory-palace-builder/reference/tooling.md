# Tooling and token economy

## Load once

Use `room_context.py` (with `--compact` for generation and `--init-manifest` for new rooms) for the resolved target brief and `unbuilt.py --building <id>` for destination coverage. It reads this checkout; pass `--sync` only when the comparison must be a fresh public main. A room is not built while a planned word is painted only in another building. Reuse the checkout and fetch main once. Read target records, required references and affected dependencies; reserve whole-repo inventories for audits. Parse/filter large payloads in code rather than writing ad-hoc one-liner scripts per field. Print findings/counts, never full registries, commit responses, prompts or binary/base64 content.

Keep one building plan, room manifest and checkpoint (base, touched paths, accepted revision, blockers, next action). `build_prompt.py --layout --write --output` checks the linked plan and saves the specification; `--check` detects drift. Save exact local-edit deltas separately, stating which specification fields they replace.

## Choose working capabilities early

Check required local executables/libraries once before expensive work. Establish a usable fallback or record the test limitation. A remote browser may not reach executor loopback; do not create extra deployments merely to test reachability.

Prefer connected GitHub publishing tools when available. Do not retry command-line pushes with credentials known absent. Reuse one route; upload changed files only, create one tree/commit and PR, verify contents/CI, then merge under existing authorization. Load transfer bytes programmatically without printing them. Preserve concurrent work and obey approval policy; never route around a rejected action.

## Reuse valid evidence

Check the walkthrough and compile the linked draft once. Use `contact_sheet.py --image --grid --anatomy-2x` to fit a candidate, then add `--layout` for measured labels, passage checks and a review packet with input hashes. Sync the manifest only for the same complete room. Reuse the reviewer and inspect required 2× details and actual parent/zoom pairs with `zoom_sheet.py`.

Use unique review paths per revision, outside the repository. Layout/`boxPx` coordinates are pixels; built `box` values are percentages. Rebuild with existing scripts, never hand-fix generated payloads or invent another geometry implementation. Run targeted iteration checks (`check_v2.py --browser --rooms-only` for room iterations) and global CI on the combined pack; reuse only results with unchanged inputs.

## Paintings that belong in git

Commit the accepted room painting and its card crops (`village/<building>/<room>.jpg` and `village/<building>/cards/`). Keep every rejected or intermediate candidate outside the repo. A short note next to the manifest may record the accepted file's sha256 and the decision. Do not commit new review rasters. The science-faculty packet already in `content/v2/sciences/review/` stays; removing it would not shrink git history.
