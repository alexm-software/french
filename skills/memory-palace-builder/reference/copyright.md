# Copyright

Read before every public release and when adding any text, data, font or code.

3. No copyright problems: write your own definitions and explanations, or use openly licensed sources with the required attribution recorded in a credits file. Generate or draw all images yourself. <!-- B59 -->
Audit everything that ships: quoted texts (prayers, poems, liturgical translations; prefer public-domain versions and check modern official translations), definitions and glosses (dictionary sources such as Wiktionary are CC BY-SA, so either attribute and share-alike or rewrite in your own words), word lists and level data (check whether redistribution is allowed), fonts (ship OFL licence files), and third-party code. Keep a COPYRIGHT_AUDIT file and a shipped CREDITS page. <!-- B116 -->

Lessons from the first audit: <!-- B117 -->

- Modern official liturgical translations are often copyrighted and need permission (e.g. AELF in French, ICEL in English). Use dated public-domain editions (e.g. 19th or early 20th century catechisms and prayer books on Wikisource), record each text's edition and URL in its data, and translate from the original yourself when no PD version exists. <!-- B118 -->
- Watch for licence clashes: a non-commercial (NC) dataset can't be mixed into share-alike (SA) public data. Keep NC values out of the shipped files and use them only internally, with credit. <!-- B119 -->
- Rewrite copied dictionary glosses in your own words sector by sector as each sector ships (it also improves quality), in a separate original-gloss file that takes precedence in the merge. <!-- B120 -->
- Credit AI image tools and disclose AI generation where their terms ask for it. <!-- B121 -->
- The public repo needs a LICENSE for the code and a data licence file that matches its share-alike sources. <!-- B122 -->
- Run the copyright check above. Every shipped text, dataset, font, image and piece of code has a known licence, and the credits page lists every attribution needed. <!-- B189 -->
