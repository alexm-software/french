# Gate tools, logs and the review loop

Read when running gates or setting up checkers.

These gates come from issues users found room after room. A space is NOT done until every gate passes, and the checker must have actually looked: view crops with an image reader, not just read the json. Record the result per space in a gates log (space | gate | pass/fail | note), with the site commit the checks ran against in the log header. Safety and content failures (gate 6) block release. Any other failure is a major issue. <!-- G10 -->

**Tools.** The automatable gates are scripted: `scripts/qa/check_v2.py --strict --placement` over the whole live site (geometry, overlaps, sides, center band, room size, one hook per word, placement; add `--browser` with a local server for the rendered checks), `tools/precheck.py` for one new or repainted room, and `tools/hook_lint.py` for the mechanical hook checks. Crop sheets come from `tools/contact_sheet.py`. Label-only fixes are edits to `labelAt` in `content/v2/<bld>/layout.json`, then a `build_v2.py --no-cards` rebuild. A gate script that exits non-zero blocks the release. Port the viewer code into the checker (font, anchor, badge placement, which controls render). Never re-guess it. After any viewer or build change, re-run every gate script on the new commit before trusting its counts. A checker that disagrees with the viewer is itself a release blocker, so fix the checker first (once, a stale checker reported 20 false gate 8 failures after the viewer already hid the duplicate sector button). Gate 13 counts in reports always come from the full measure with CLIP; a run without it is only a smoke test. Keep ONE canonical copy of each gate script in the project's scripts/qa/ and update it in the same change as any viewer change; a track-local port is fine for a draft, but the release decision runs the canonical script. Write each run's log to its own dated file, so a smoke run never overwrites the full CLIP run (once, the live viewer had used a breadcrumb for hours while the gate script still modeled the old Back button). <!-- G12 -->

## Cheap checks first, then one contact sheet per room

- **Order:** (1) `tools/unbuilt.py` at the start of the job; (2) `tools/precheck.py IMAGE --data village/data/<bld>.js --room <key> --manifest m.json` on every new or repainted room: 1280x720 size, OCR text FLAGS (human decides, never auto-reject), label/hotspot/door/mapExit/zoom-badge/nameplate overlap and 3 px touching (check_v2 geometry), label detached from its box, center band, and manifest completeness (every word present, what is shown, pose, exact counts, where verbs act, sensitive treatment, doors/exits); fix every FAIL first; (3) the project's own gate scripts (check_v2 strict/placement/browser); (4) visual review. <!-- N3 -->
- **Visual review unit:** ONE downscaled contact sheet per room (`tools/contact_sheet.py`): the painting with boxes, labels, doors and OCR flags drawn on, the browser shot beside it when one exists, and a 256 px card-crop tile per item and exit with its headword and hook (gate A). Open a full-size crop only where a tile raises doubt (anatomy, counts, small-prop text, hook objects, edges). This replaces separate per-item full-size views; it does not drop any gate: every item and exit is still looked at. <!-- N3 G23 -->
