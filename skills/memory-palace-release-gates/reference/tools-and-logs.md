# Gate tools, logs and the review loop

Read when running gates or setting up checkers.

These gates come from issues users found room after room. A space is NOT done until every gate passes, and the checker must have actually looked: view crops with an image reader, not just read the json. Record the result per space in a gates log (space | gate | pass/fail | note), with the site commit the checks ran against in the log header. Safety and content failures (gate 6) block release. Any other failure is a major issue. <!-- G10 -->

**Tools.** The automatable gates are scripted where the project has them, e.g. `scripts/qa/release_gates.py` for gates 7, 8, 9a, 12 and 13 over the whole live site, built with the site's own build script, `scripts/qa/package_gates.py` for one package, and `scripts/qa/label_overlap.py` for gate 7 detail. Crop sheets come from `scripts/qa/hook_sheets.py`, label-only fixes from `scripts/qa/label_fix.py`, and the procedure is in `scripts/qa/hook_image_match.md`. A gate script that exits non-zero blocks the release. Port the viewer code into the checker (font, anchor, badge placement, which controls render). Never re-guess it. After any viewer or build change, re-run every gate script on the new commit before trusting its counts. A checker that disagrees with the viewer is itself a release blocker, so fix the checker first (once, a stale checker reported 20 false gate 8 failures after the viewer already hid the duplicate sector button). Gate 13 counts in reports always come from the full measure with CLIP; a run without it is only a smoke test. Keep ONE canonical copy of each gate script in the project's scripts/qa/ and update it in the same change as any viewer change; a track-local port is fine for a draft, but the release decision runs the canonical script. Write each run's log to its own dated file, so a smoke run never overwrites the full CLIP run (once, the live viewer had used a breadcrumb for hours while scripts/qa/release_gates.py still modelled the old Back button). <!-- G12 -->

## Cheap checks first, then one contact sheet per room (v13)

- **Order:** (1) `tools/unbuilt.py` at the start of the job; (2) `tools/precheck.py IMAGE --data village/data/<bld>.js --room <key> --manifest m.json` on every new or repainted room: 1280x720 size, OCR text FLAGS (human decides, never auto-reject), label/hotspot/door/mapExit/zoom-badge/nameplate overlap and 3 px touching (check_v2 geometry), label detached from its box, centre band, and manifest completeness (every word present, what is shown, pose, exact counts, where verbs act, sensitive treatment, doors/exits); fix every FAIL first; (3) the project's own gate scripts (check_v2 strict/placement/browser); (4) visual review. <!-- N3 -->
- **Visual review unit:** ONE downscaled contact sheet per room (`tools/contact_sheet.py`): the painting with boxes, labels, doors and OCR flags drawn on, the browser shot beside it when one exists, and a 256 px card-crop tile per item and exit with its headword and hook (gate A). Open a full-size crop only where a tile raises doubt (anatomy, counts, small-prop text, hook objects, edges). This replaces separate per-item full-size views; it does not drop any gate: every item and exit is still looked at. <!-- N3 G23 -->
